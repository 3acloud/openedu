# 晨桥手记 · 初高衔接规划

这是一个面向初升高学生的衔接规划网页应用，包含首页、制定计划、计划册三个页面。根据学生所处阶段、选科意向、可用时间，以及数学、物理、化学、英语的自查情况，提交后由后台生成先补基础、再看高一入口、且每周留有完整休息日的 Markdown 计划。页面只负责采集、展示、修订和删除，不代替学生决定选科。

不包含登录页。表「衔接规划」已存在，不要改表结构，不要新增字段。本表没有创建日期字段，也没有自动编号 ID 字段，禁止编造计划编号、记录ID、创建日期等字段名。布尔值本表未使用。所有出现的操作按钮都必须真正实现，不能只做样式。

统一主题「晨桥手记」：暖纸色页面背景（#f3efe4），墨蓝导航（#1e3554），杏橙强调（#c56a32），松绿用于休息、完成与次要成功态（#3c7564）。标题用中文衬线，正文用柔和无衬线。卡片白底、左侧色条、圆角，悬停轻微上浮。最担心学科用固定色标：数学靛蓝、物理青、化学紫、英语杏。整体像一本安静的衔接手记，不使用成绩排名、倒计时压力或红色警示风格。窄屏时导航收成菜单，卡片改为单列。

数据源一律写作：衔接规划/默认表格
字段名必须严格使用：所处阶段、高考模式、选科意向、距开学周数、每日可学时间（分钟）、最担心学科、四科学情与卡点、衔接计划
操作表只通过下列桥接，不要自造接口：
	callAppBridge({type:"GetTableCSV", data:"衔接规划/默认表格", payload:"逗号分隔的字段名"})，返回不含标题行的 csv。行序即行号，从 1 开始。
	callAppBridge({type:"GetRecordCount", data:"衔接规划/默认表格"})
	callAppBridge({type:"GetCellValue", data:"衔接规划/默认表格", payload:"字段名/行"})
	callAppBridge({type:"SetCellValue", data:"衔接规划/默认表格", payload:"字段名/行/值"})
	callAppBridge({type:"SubmitRecord", data:"衔接规划", payload:"表单JSON文本"})
	callAppBridge({type:"DeleteRecord", data:"衔接规划/默认表格", payload:"行号字符串"})，行号必须先 toString()
	需要按字段值定位行时才用 callAppBridge({type:"GetRecordRow", data:"衔接规划/默认表格", payload:"字段名/值"})，行号从 1 开始
列表与详情用到的用户字段，GetTableCSV 与表单字段保持同一套，以便点行修订。

	修订已有记录时，只对用户字段依次 SetCellValue，不用 SubmitRecord，也不要改衔接计划。

制定计划
	左上标题随模式变化：新建时为「制定衔接计划」，说明「写下阶段、时间和四科卡点。信息不足时，生成结果会先列出要补充的自查问题，不会编造学情。」修订时为「修订学情」，说明「保存修订只更新这条记录的学情，不会重新生成衔接计划。若要一份新计划，请另存为新计划。」
	右上按钮：查看计划册，跳转计划册
	当前行初始为 0。页面为左表单、右阅读区。窄屏改为上下排列。
	表单分三步，仅切换可见分组，不分别提交
		步骤一「阶段」：所处阶段，两枚大选项卡，只能选「中考后至高一开学前」或「高一开学至上学期期中」。选中「高一开学至上学期期中」时，在字段下提示：计划会优先处理已经开始跟不上的章节，距开学周数可填 0。
		步骤二「时间与方向」：高考模式（3+1+2、3+3、不清楚）；选科意向单行文本，占位「如物理、化学、生物；未确定就写倾向，不要指望这里替你定科」；距开学周数，非负整数；每日可学时间（分钟），1 到 600 的整数。高考模式为「不清楚」时提示：可以生成衔接节奏，但不会替你决定选科。
		步骤三「四科自查」：最担心学科四选一；四科学情与卡点为多行文本。按钮「填入四科提纲」：若文本为空则写入四行「数学：」「物理：」「化学：」「英语：」，若已有内容则不覆盖，只在末尾补上缺少的科目行。提纲按钮只改本地文本。
		底部步骤按钮：上一步、下一步。第一步上一步不可用，第三步下一步不可用。这两枚按钮不提交数据。
	底部主操作随模式变化，都必须实现
		新建模式按钮：生成衔接计划
			提交前校验：所处阶段、高考模式、最担心学科必选；距开学周数为大于等于 0 的整数；每日可学时间为 1 到 600 的整数；四科学情与卡点去掉空白后不能为空。选科意向可空。校验失败时在字段旁说明，不提交。
			通过后 callAppBridge({type:"SubmitRecord", data:"衔接规划", payload:JSON文本})。JSON 只含七个用户字段，数值用数字，不要包含衔接计划，不要编造 ID。
			提交成功后当前行设为 1，右侧进入等待态，文案：「正在诊断四科衔接缺口，并安排带休息日的每周计划…」
			轮询衔接计划，不轮询其他字段。每 2 秒调用一次 GetCellValue，payload 为「衔接计划/1」。得到非空文本后停止轮询，用 Markdown 主题渲染到右侧「衔接计划」。空文本则继续等待。提供「停止等待」按钮，只停止轮询，不删除记录。
			生成完成后刷新首页会用到的计数概念：本页不展示统计，但计划册下次进入要重新 GetTableCSV。
		修订模式按钮：保存修订
			对当前行依次 SetCellValue 七个用户字段，payload 形如「所处阶段/3/中考后至高一开学前」。不要 SetCellValue 衔接计划，不要 SubmitRecord。
			保存成功后提示「学情已更新，原衔接计划仍保留」，并重新 GetCellValue 刷新右侧已有计划。
		修订模式另有按钮：按当前内容另存为新计划
			先做与新建相同的校验，再 SubmitRecord 一份新记录，不删除旧行。提交后当前行变为 1，按新建规则轮询「衔接计划/1」，并用 Markdown 显示新计划。成功后模式改回新建结果态，提示这是新记录，旧记录仍在计划册。
		按钮：清空并新建。清空全部输入与右侧 Markdown，当前行设为 0，切回新建模式，不删除任何记录。
	右侧阅读区
		标题：衔接计划
		新建未提交时占位：「提交后，这里只呈现一份 Markdown 计划。」
		有内容时用 Markdown 主题显示，保留标题、列表和每周安排，不改写成另一套格式。
		按钮：复制计划。把当前 Markdown 原文复制到剪贴板，成功后按钮短时变为「已复制」。无内容时按钮不可用。
		阅读区右上角：按钮 <、按钮 >
			API名称:GetRecordCount,数据源:衔接规划/默认表格
			点击 < 或 > 时，按方向改变当前行，并用 GetCellValue 逐字段读取七个用户字段与衔接计划，填入表单和阅读区，模式改为修订。
			当前行小于等于 1 时，< 不可用。当前行大于等于记录数，或当前行为 0 时，> 不可用。当前行为 0 时 < 也不可用。

计划册

	说明：每一条都是一次四科自查和当时生成的衔接计划。点卡片主体可修订学情；看全文请打开详情。

	搜索框：匹配选科意向、四科学情与卡点、最担心学科，输入即在已取回的数据中筛选
	筛选器：所处阶段、高考模式、最担心学科，均可选「全部」或对应可选项。按钮「清除筛选」恢复全部。
	排序：默认行号升序（最新提交在前）；可切换为距开学周数从少到多。排序只影响当前列表，不改表。
	进入页面时取列表
		API名称:GetTableCSV,数据源:衔接规划/默认表格,字段:[所处阶段,高考模式,选科意向,距开学周数,每日可学时间（分钟）,最担心学科,四科学情与卡点,衔接计划]
		csv 无标题行。展示字段与表单用户字段一致；衔接计划列不在卡片中展开全文，最多显示前 28 字作为「计划已生成 / 尚未生成」的辅助，空则显示「计划生成中或尚未返回」。
	主体用卡片列表，不用单独的只读表格页。每张卡片包含
		所处阶段、高考模式、最担心学科色标
		选科意向，空则「选科尚未写明」
		距开学周数、每日可学时间（分钟）
		四科学情与卡点前 80 字
		操作：查看计划、修订、删除。三个按钮都要可用
	点击卡片主体或「修订」：当前行设为该行号，跳到制定计划的修订模式，用 GetCellValue 逐字段填充七个用户字段，并取衔接计划用 Markdown 显示在右侧。不要用 SubmitRecord 加载。
		API名称:GetCellValue,数据源:衔接规划/默认表格,字段名:所处阶段,行号:当前行
		其余字段同样 GetCellValue：高考模式、选科意向、距开学周数、每日可学时间（分钟）、最担心学科、四科学情与卡点、衔接计划
	查看计划：打开本页右侧或全屏详情层，不离开计划册
		头信息来自该行七个用户字段；若刚从首页点入，也用 GetCellValue 重新取，保证与单元格详情一致
		正文只渲染 GetCellValue 得到的衔接计划，Markdown 主题。内容为空时显示「这条记录的衔接计划还没有生成完成」，并提供「刷新计划」按钮，仅再次 GetCellValue 衔接计划，不重新提交。
		详情层按钮：复制计划、修订此条、删除此条、关闭。复制与修订、删除的行为与卡片按钮相同。

	无记录、或筛选后为空：空状态文案「没有符合条件的手记」，并提供「制定新计划」按钮。
	列表不提供未实现的导出、分享、打印按钮。

全局交互
	单选项只能选择表定义中的可选项，不能手输新选项。
	数值字段在界面上用数字输入，提交 JSON 时用数字；SetCellValue 的值用该字段的文本形式。
	任何页面不要出现登录、注册、权限、支付。
	不要调用选择图片、拍照、语音、文件上传相关桥接，本表没有这些字段。
	不要把衔接计划当成手工字段去提交。指令描述没有要求 JSON，因此只轮询「衔接计划」。
	详情与生成结果中的衔接计划一律 Markdown 主题显示。界面固定提示一句：计划用于安排衔接，不代替学生决定选科。
	操作失败时在页面内短提示，保留用户已填写内容。
