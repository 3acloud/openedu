# 费曼理解检验

这是一个让学生用自己的话讲解知识点、再阅读导师检验反馈的网页应用。包含三个页面：首页、开始检验、检验档案。不要登录页。不要调用外部大模型，不要在前端自行追问、打分或改写反馈。理解检验只由数据表「理解检验」的「检验反馈」指令流在 SubmitRecord 之后由后台生成。前端负责采集讲解、提交、轮询、用 Markdown 呈现，以及档案管理。

应用气质是深夜书房里的一本讲解笔记，不要做成绿色生产后台，也不要做成植物识别页。背景为暖米纸色渐变（#F4EFE4 到 #E7F0F4），主色墨蓝 #1E3A5F，强调色暖琥珀 #D4890B，点缀珊瑚 #C46B5A 与青灰 #5E8B7A。卡片如纸页：大圆角、细墨蓝描边、轻阴影；悬停时上浮 4px，左侧出现 3px 琥珀边。按钮为墨蓝实心或琥珀描边，点击有轻微按压。字体使用柔和无衬线。学段徽章颜色固定：小学中段青灰、小学高段湖蓝、初中琥珀、高中墨蓝。空状态用一句短文案和一枚简易灯泡线稿，不要外链图片。

页面顶部固定导航栏，墨蓝底、浅色字。
	左侧为灯泡线标和「费曼理解检验」
	右侧标签：首页、开始检验、检验档案
	当前页标签用琥珀下划线。窄屏时标签改为顶部横向滚动，不隐藏。

本表只有这些字段，禁止编造记录编号、创建日期、状态、等级、图片或任何关联表：学段（单选项：小学中段、小学高段、初中、高中）、知识点（文本）、我的讲解（文本）、检验反馈（指令流，只读）。无布尔字段。无自动编号字段，不要生成随机 ID。检验反馈不是用户填写项，禁止出现在可编辑输入框里，禁止对它调用 SetCellValue。

数据源一律写「理解检验/默认表格」。提交用的表名一律写「理解检验」。GetTableCSV 返回不含标题行的 csv，字段顺序与 payload 一致。讲解文本可能含逗号和换行，禁止用简单 split(',') 切列；解析失败时不要猜字段，打开某一行时一律以行号调用 GetCellValue 为准。CSV 第 i 条（从 0 起）对应原始行号 i+1。搜索和筛选只在前端做，删除、编辑、翻页必须使用原始行号，不能使用筛选后的序号。新提交的记录在第 1 行。当前行初始为 0。

## 首页

主标题：费曼理解检验
说明：用自己的话讲清楚，才知道自己卡在哪里。导师会按学段追问；证据不够时只问最关键的一个问题，证据够了才给出掌握情况和下一步。

主按钮：开始一次检验，跳转到「开始检验」，并清空为新检验态（当前行=0）。

其下是四张可点击的学段丝带，文案固定：
	小学中段：用自己的话讲明白，并举一个生活例子
	小学高段：讲清楚是什么、为什么，再举一个例子
	初中：解释、举例、说原因，并换个情境用一次
	高中：在此之上，检查这个说法的边界和反例
点击丝带跳转到「开始检验」，预选对应学段，其余为空。

接下来三张并列统计卡，悬停上浮：
	累计检验：callAppBridge({type:"GetRecordCount", data:"理解检验/默认表格"})
	小学检验：callAppBridge({type:"GetTableCSV", data:"理解检验/默认表格", payload:"学段,知识点,我的讲解"})，统计学段为「小学中段」或「小学高段」的条数
	中学检验：同一份 CSV，统计学段为「初中」或「高中」的条数
记录数为 0 时，三张卡显示 0，不要报错。

再往下是「最近讲解」卡片列表，标题右侧小字：新的检验排在最前。取上述 CSV 前 5 条；没有记录时显示「还没有讲解，先去讲一个你正在学的知识点」。每张卡片显示学段徽章、知识点、我的讲解前 60 字。仅这 5 条额外取反馈摘要：callAppBridge({type:"GetCellValue", data:"理解检验/默认表格", payload:"检验反馈/"+行号})，截取前 40 字，空则显示「反馈生成中或尚未查看」。点击卡片不是就地展开，而是进入「开始检验」的查看态并载入该原始行号。

首页底部一条细字说明：若讲解里带着明显的挫败，导师会放慢追问。前端不拦截提交，也不另外生成劝慰文案。

## 开始检验

左上大标题：开始检验
说明：先选学段，再写下你自己的讲解。提交后请停留在本页，等导师笺写完。
右上按钮：看检验档案，跳转到「检验档案」。

页面主体为左右两栏；窄屏改为上讲解、下导师笺。

左栏标题：我的讲解本。顶部三步只作示意，不写库：1 选学段、2 自己讲、3 看追问。

学段为四张单选卡片，不是下拉框，必须四选一，选项仅限：小学中段、小学高段、初中、高中。选中卡片墨蓝底白字。未选时不能提交。

知识点为单行文本，占位：例如「分数的意义」「光合作用」「牛顿第一定律」。

我的讲解为多行文本，最少 6 行，右下显示已输入字数（仅界面计数，不是字段）。占位随学段变化：
	小学中段：像讲给同学听一样，说说它是什么，再举一个生活里的例子。
	小学高段：用自己的话讲清楚它是什么、为什么这样，并举一个例子。
	初中：先解释，再举例，说明原因，并试着换一个情境用一次。
	高中：除了解释、举例、原因和迁移，请想一想：这个说法在什么情况下会不成立？
讲解本下方始终显示一句提醒：请用自己的话，不要粘贴现成答案。若导师觉得像引用，会请你脱离原话再讲一次。不要在前端检测是否为 AI 文本。

学段提示条（只读，随学段切换，不入库）：
	小学中段、小学高段：适用步骤是自己的话、举例、说明原因、换个例子再用一次。
	初中、高中：除上述步骤外，还会做批判性验证。
证据不足时，导师只会留下当前最关键的一个追问，此时不要期待等级。

左栏主按钮随状态变化，同一时刻只出现一种主操作：
	新检验态（当前行=0）：按钮「请帮我检验」。知识点或我的讲解为空，或未选学段时禁用。
	查看态（当前行>=1 且未点编辑）：隐藏该按钮，避免误当成更新。
	编辑态：按钮改为「保存修改」，不走提交。

新检验提交：
	表单标题:理解检验,表:理解检验,字段:[{字段名:学段,类型:单选项,可选项:小学中段,小学高段,初中,高中},{字段名:知识点,类型:文本},{字段名:我的讲解,类型:文本},{字段名:检验反馈,类型:指令流}]
	检验反馈不放入 payload。
	callAppBridge({type:"SubmitRecord", data:"理解检验", payload:JSON.stringify({"学段":学段,"知识点":知识点,"我的讲解":我的讲解})})
	提交成功后当前行设为 1，左栏改为查看态，立刻进入轮询。提交过程中禁用按钮，防止重复提交。

轮询只针对指令流字段「检验反馈」。指令描述没有要求「以JSON格式输出」，所以不要轮询别的字段，也不要按 JSON 解析。
	轮询标题:理解检验,表:理解检验,字段:检验反馈,输出到:导师笺,等待消息:导师正在对照你的讲解找盲区...
	循环调用 callAppBridge({type:"GetCellValue", data:"理解检验/默认表格", payload:"检验反馈/1"})，约每 1 秒一次。
	得到非空文本后停止，把全文用 Markdown 主题渲染到右栏，不要截断。
	最多轮询 40 次。超时则导师笺显示：反馈还在生成，可稍后在检验档案打开第 1 条查看。不要自行编造等级或追问。

右栏标题：导师笺。右上角是「<」「>」，用于按行翻阅，不新开页面。
	callAppBridge({type:"GetRecordCount", data:"理解检验/默认表格"}) 得到记录数。
	当前行<=1 时，「<」不可操作。
	当前行>=记录数或记录数为 0 时，「>」不可操作。
	当前行为 0 时两个箭头都不可操作。
	点击「<」或「>」后，当前行加一或减一，左栏进入查看态，逐字段读取并填充，右栏渲染该行检验反馈：
		callAppBridge({type:"GetCellValue", data:"理解检验/默认表格", payload:"学段/"+当前行})
		callAppBridge({type:"GetCellValue", data:"理解检验/默认表格", payload:"知识点/"+当前行})
		callAppBridge({type:"GetCellValue", data:"理解检验/默认表格", payload:"我的讲解/"+当前行})
		callAppBridge({type:"GetCellValue", data:"理解检验/默认表格", payload:"检验反馈/"+当前行})
	检验反馈为空时，右栏显示「这条还没有反馈」，不要用左边讲解冒充反馈。

查看态右栏反馈 Markdown 下方有三个按钮，都必须实现：
	针对追问，再讲一次：进入新检验态，预填当前学段和知识点，讲解框清空但在上方保留一张只读「上一则导师笺」摘要（前 120 字，完整内容仍在右栏），方便学生针对追问重讲。当前行先保持，直到新的 SubmitRecord 成功后才变为 1 并重新轮询第 1 行。这是新记录，不是 SetCellValue。
	编辑这条：进入编辑态，三个输入可改，检验反馈仍只读。保存时依次调用，且只调用这三项：
		callAppBridge({type:"SetCellValue", data:"理解检验/默认表格", payload:"学段/"+当前行+"/"+学段值})
		callAppBridge({type:"SetCellValue", data:"理解检验/默认表格", payload:"知识点/"+当前行+"/"+知识点值})
		callAppBridge({type:"SetCellValue", data:"理解检验/默认表格", payload:"我的讲解/"+当前行+"/"+讲解值})
		保存成功后仍停留查看态，并提示：讲解已改，但检验反馈不会因此重算；要新的追问请用「针对追问，再讲一次」。
	删除这条：先确认「删除后不能恢复」。确认后 callAppBridge({type:"DeleteRecord", data:"理解检验/默认表格", payload:当前行.toString()})。成功后当前行设为 0，清空左右栏，并刷新记录数。payload 必须是文本，所以行号先 toString()。

右栏在当前行为 0 且未提交时，显示空状态：把你的讲解交给导师。证据不够时，这里会出现一个追问；证据够了，才会看到掌握度和下一步。不要预放 A/B/C/D。

左上另外有文字按钮「新的检验」：清空学段、知识点、我的讲解和导师笺，当前行设为 0，回到新检验态。

从首页或档案载入某行时，走与「<」「>」相同的 GetCellValue 查看态，不自动提交。

## 检验档案

左上大标题：检验档案
说明：回看自己讲过的知识点。点卡片查看导师笺，而不是另开只读页。
右上按钮：+ 新的检验，跳转到「开始检验」的新检验态。

搜索框：按知识点或我的讲解包含匹配，不区分大小写，输入即筛选。
筛选器：全部学段，以及小学中段、小学高段、初中、高中。与搜索同时生效。
无匹配时显示「没有符合的讲解」。

数据：
	callAppBridge({type:"GetTableCSV", data:"理解检验/默认表格", payload:"学段,知识点,我的讲解"})
列表用卡片，不用大表格。每张卡片显示学段徽章、知识点、我的讲解前 80 字，以及原始行号小字（便于核对，不可编辑）。默认顺序与 CSV 一致，第 1 行在最前。不提供按日期排序，因为表内没有日期字段。

每张卡片底部四个按钮都要实现，点击按钮时不要把事件冒泡成“只查看”：
	查看：跳转「开始检验」查看态，当前行=该卡片原始行号，GetCellValue 填充四字段，检验反馈用 Markdown 显示。
	编辑：同样载入该行后直接进入编辑态。
	再讲一次：载入该行的学段和知识点到新检验态，规则同开始检验页的「针对追问，再讲一次」。
	删除：确认后 callAppBridge({type:"DeleteRecord", data:"理解检验/默认表格", payload:原始行号.toString()})，然后重新 GetTableCSV 刷新卡片。删除的是原始行号，不是卡片在筛选结果中的序号。

点击卡片空白处等同于查看。

若需按知识点定位行号，可调用 callAppBridge({type:"GetRecordRow", data:"理解检验/默认表格", payload:"知识点/"+知识点值})。知识点可能重复，因此卡片操作优先使用打开列表时记下的原始行号，不要依赖 GetRecordRow 的第一次命中。

## 实现约束

三个页面切换不整页刷新丢失未提交草稿；离开「开始检验」前提示「讲解还没提交，确定离开吗」，仅在新检验态且讲解非空时提示。
所有已写出的按钮、箭头、搜索、筛选、学段丝带、统计卡都必须可用，不能只做样式。
主体列表的 GetTableCSV 字段与可编辑表单字段一致，为学段、知识点、我的讲解，以便点卡片载入后编辑。检验反馈只通过 GetCellValue 读取，并用 Markdown 主题显示标题、列表和强调，不要把 Markdown 源码直接当纯文本扔进白色预。
不要展示创建日期或自动编号。不要 SelectImage、SelectFile、录音或上传，讲解只来自文本框。
接口失败时在对应区域显示短错误，保留用户已输入的讲解。
全站沿用同一套纸页主题、徽章色和悬停效果。
