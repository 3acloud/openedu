# 数学错因分析
	这是一个数学错因分析网页应用，单页切换三个视图：首页、错题工作台、分析档案。不做用户登录页。不要新增表定义以外的字段，不要出现记录编号、学员姓名、学号、班级号、分数、创建日期、排名等自造字段。本表只有两个字段：错题记录（文本，用户填写）、分析报告（指令流，任务智能体，用户不可手填）。
	统一主题「靛蓝教研室」：背景为暖纸色 #F3EFE4，顶部导航为靛蓝渐变 #1B2A4A 到 #2C4A7C，点缀淡金 #C6A15B 细线与简易函数曲线 Logo。卡片像方格稿纸，细边框 #E4DCC8，悬停轻抬升。字体用 Noto Sans SC 等无衬线字体。七类错因只用固定色点作图例，不作统计图：概念模糊 #7C6A9A、规则错误 #C45C26、审题错误 #2F6F8F、策略错误 #3D6B4F、计算错误 #A33B3B、粗心大意 #B8860B、知识漏洞 #5C4A3A。窄屏改为上下堆叠。所有按钮必须真正可用，禁用态要有原因。
	数据约定（操作表只能按下列桥接，数据源一律写「错因分析/默认表格」，提交表名一律写「错因分析」）
		列表：callAppBridge({type:"GetTableCSV", data:"错因分析/默认表格", payload:"错题记录,分析报告"})，返回不含标题行的 CSV。字段顺序与表单一致，以便点一行就能载入表单。按 CSV 规则解析引号与逗号；报告正文展示不得依赖可能被换行拆开的 CSV，必须以 GetCellValue 为准。
		条数：callAppBridge({type:"GetRecordCount", data:"错因分析/默认表格"})
		定位：callAppBridge({type:"GetRecordRow", data:"错因分析/默认表格", payload:"错题记录/值"})，行号从 1 开始。卡片行号默认等于 CSV 行序（第一行是 1）；拿不准时用 GetRecordRow 复核。
		详情：callAppBridge({type:"GetCellValue", data:"错因分析/默认表格", payload:"字段名/行号"})
		新建：callAppBridge({type:"SubmitRecord", data:"错因分析", payload:JSON文本})。JSON 只含错题记录，正确转义引号和换行。提交成功后当前行必为 1。不要把分析报告放进提交 JSON。
		修订：只对错题记录依次 SetCellValue，禁止用 SubmitRecord 改旧行，禁止 SetCellValue 写分析报告。callAppBridge({type:"SetCellValue", data:"错因分析/默认表格", payload:"错题记录/行号/修订全文"})
		删除：先确认，再 callAppBridge({type:"DeleteRecord", data:"错因分析/默认表格", payload:行号.toString()})。payload 必须是文本。
		读入文本文件：callAppBridge({type:"SelectFile"}) 得到全局文件名，再 callAppBridge({type:"ReadFile", data:"全局文件名"})，把文本填入错题记录输入框，不自动提交。失败则提示「无法读取该文件，请改为粘贴文本」。不要把全局文件名存进错题记录。
		分析报告是指令流。指令类型为任务智能体，指令描述为：使用技能 xiaozhi-teach-math-error-analyzer 分析以下匿名化数学错题记录：{{错题记录}}。按概念模糊、规则错误、审题错误、策略错误、计算错误、粗心大意、知识漏洞七类识别错因，关联相关及前置知识点，形成班级共性与学员个体画像，给出具体教学干预、复测与重复错因追踪建议。仅依据记录中的信息分析；证据不足时说明待核实，不编造人数、比例或趋势；使用化名或编号，不排名。以一份 Markdown 文本报告输出。
		前端不得自行调用该技能，不得编造报告、人数、比例或趋势。指令描述没有「以JSON格式输出」，因此提交后只轮询分析报告。轮询：每 2 秒 callAppBridge({type:"GetCellValue", data:"错因分析/默认表格", payload:"分析报告/当前行"})，得到非空文本即停，并用 Markdown 主题渲染。等待文案：「正在识别七类错因并撰写干预与复测建议…」。超过 90 秒仍为空则停止，提示稍后在分析档案查看，页面保持空白报告，不填占位结论。
		当前行初始为 0。提交、修订、删除后都重新 GetRecordCount 和 GetTableCSV，刷新首页与档案。不提供学员排名、分数榜、错因占比图。
	页面顶部导航栏
		左侧：金色函数曲线 Logo +「数学错因分析」
		右侧标签：首页、错题工作台、分析档案。当前标签用金色下划线。
	首页
		主标题：数学错因分析
		说明：汇总匿名化数学错题记录，识别七类错因和知识点薄弱环节，形成班级共性与学员画像，并给出教学干预、复测与重复错因追踪建议。请只使用已匿名化的记录。
		按钮「开始错因分析」：切换到错题工作台，当前行设为 0，清空输入框和报告区。
		按钮「查看分析档案」：切换到分析档案。
		两张真实数据卡片，数字只能来自接口
			档案总数：callAppBridge({type:"GetRecordCount", data:"错因分析/默认表格"})。无记录显示 0。
			最新报告：总数为 0 时显示「尚无」，且不请求单元格。总数大于 0 时 callAppBridge({type:"GetCellValue", data:"错因分析/默认表格", payload:"分析报告/1"})，空则显示「生成中」，非空显示「已生成」。点击「已生成」或「生成中」都打开第 1 行详情。
		七类错因图例：七枚色点加名称，标题写明「错因分类图例，不是统计」。不要按类别计数。
		最近分析：标题「最近分析」。callAppBridge({type:"GetTableCSV", data:"错因分析/默认表格", payload:"错题记录,分析报告"})，取前 4 行，不足 4 行则全显示。卡片只展示错题记录前 80 字；分析报告不在卡片上铺全文。无数据时显示「还没有错因分析，从一条匿名错题记录开始」，并给出「开始错因分析」按钮。
		点击最近卡片：切换到分析档案，打开该行详情抽屉。行号即 CSV 行序。详情必须再取 GetCellValue，不能只用卡片摘要。
	错题工作台
		左上标题：错题工作台。说明：左侧贴入匿名错题记录，右侧等待后台生成的 Markdown 报告。证据不足时报告会写待核实，界面不要补写结论。
		右上按钮「新建」：清空错题记录输入框和分析报告区，当前行设为 0，不删除任何记录。
		左侧稿纸
			多行输入框，标签「错题记录」，占位：「粘贴匿名化错题记录。不要写真实姓名、学号或联系方式。」
			按钮「从文本文件读入」：SelectFile 后 ReadFile，成功则覆盖输入框。
			按钮「生成分析」：仅当当前行是 0 且错题记录去掉空白后非空时可点。点击后提交
				表单标题:错因分析,表:错因分析,字段:[{字段名:错题记录,类型:文本},{字段名:分析报告,类型:指令流,指令类型:任务智能体,指令描述:"使用技能 xiaozhi-teach-math-error-analyzer 分析以下匿名化数学错题记录：{{错题记录}}。按概念模糊、规则错误、审题错误、策略错误、计算错误、粗心大意、知识漏洞七类识别错因，关联相关及前置知识点，形成班级共性与学员个体画像，给出具体教学干预、复测与重复错因追踪建议。仅依据记录中的信息分析；证据不足时说明待核实，不编造人数、比例或趋势；使用化名或编号，不排名。以一份 Markdown 文本报告输出。"}]
				分析报告不渲染成输入框。没有需要隐藏的编号或日期字段，不要自造后再隐藏。
				callAppBridge({type:"SubmitRecord", data:"错因分析", payload:"{\"错题记录\":\"输入全文\"}"})，payload 用实际 JSON 文本。
				提交后当前行设为 1，立即按数据约定轮询分析报告/1，输出到右侧报告区。
			按钮「保存修订」：仅当前行大于等于 1 且错题记录有改动时可点。点击后只 callAppBridge({type:"SetCellValue", data:"错因分析/默认表格", payload:"错题记录/当前行/修订全文"})。保存成功提示「错题记录已更新。修订不会自动重跑分析；要新报告请点新建后再生成。」不要改分析报告单元格。
		右侧报告纸
			标题「分析报告」。右上角按钮「上一条」「下一条」。
			先 callAppBridge({type:"GetRecordCount", data:"错因分析/默认表格"}) 得到档案总数。
			当前行小于等于 1 时「上一条」不可点。当前行为 0 或当前行大于等于档案总数时「下一条」不可点。
			「上一条」：当前行减 1，再 GetCellValue 读取错题记录与分析报告并填充左右两侧。
			「下一条」：当前行加 1，同样用 GetCellValue 填充。
			callAppBridge({type:"GetCellValue", data:"错因分析/默认表格", payload:"错题记录/当前行"})
			callAppBridge({type:"GetCellValue", data:"错因分析/默认表格", payload:"分析报告/当前行"})
			分析报告用 Markdown 主题显示标题、列表和强调。空报告且刚提交或该行仍在生成时，显示等待文案并轮询该行的分析报告。当前行为 0 时报告区显示「生成分析后，报告将出现在这里」。
			若 GetCellValue 得到的错题记录与输入框不一致，以单元格值为准回填，避免上下条串行。
	分析档案
		左上标题：分析档案。说明：回看每次分析的错题记录与报告。只按记录先后浏览，不排名。
		右上按钮「新建分析」：去错题工作台，当前行设为 0 并清空表单。
		搜索框：按错题记录全文包含关键字筛选，清空则恢复全部。不搜索不存在的字段。
		筛选条：全部，以及七类错因名称。选某一类时，只保留分析报告文本包含该名称的行；判定文本来自该行 GetCellValue 的分析报告，不要用关键词出现次数冒充人数或比例。
		主体用卡片列表，不用另一张只读表页面。数据来自 callAppBridge({type:"GetTableCSV", data:"错因分析/默认表格", payload:"错题记录,分析报告"})。每张卡片对应表单的同一组字段：错题记录显示前 120 字，分析报告只显示前 40 字摘录或「报告生成中」。卡片不显示自造编号。
		排序：保持 CSV 行序，第 1 行在最前（新建提交后最新记录在第 1 行）。不要按姓名、分数或错因轻重排序。
		点击卡片：打开详情抽屉，当前行设为该行号。用 GetRecordRow 复核可选。抽屉内
			callAppBridge({type:"GetCellValue", data:"错因分析/默认表格", payload:"错题记录/当前行"}) 显示全文
			callAppBridge({type:"GetCellValue", data:"错因分析/默认表格", payload:"分析报告/当前行"}) 用 Markdown 主题显示。空则显示「报告尚未生成」，可按钮「继续等待」并按轮询规则只轮询该行分析报告。
		抽屉按钮都必须实现
			「修订错题记录」：抽屉内出现错题记录编辑框，初始值为 GetCellValue 结果。按钮「保存修订」调用 SetCellValue 写回该行错题记录，成功后刷新卡片摘录。分析报告保持只读。
			「在工作台打开」：切换到错题工作台，当前行不变，两侧用这一行的 GetCellValue 结果填充。
			「删除」：确认文案「删除后无法恢复，确定删除这条错因分析吗？」。确认后 callAppBridge({type:"DeleteRecord", data:"错因分析/默认表格", payload:当前行.toString()})，关闭抽屉，当前行设为 0，重新拉取条数和 CSV。取消则不调用删除。
			「关闭」：只关闭抽屉，不改数据。
		无匹配结果时显示「没有符合条件的分析档案」，不要造一条示例记录。
	交互收尾
		首页最近卡片、档案卡片、工作台上下条，看到的分析报告都必须来自对应行的 GetCellValue，并用同一套 Markdown 样式。
		任何等待、失败、空数据都只说明状态，不补写错因、人数、比例、趋势或教学结论。
