# 青笺课后档案

这是一个供教师使用的课后教学档案网页应用，包含四个页面：灯下台、学员名册、课后记录、档案审阅。不包含登录页。学员只使用化名，不新增真实姓名、电话、学校、住址、家长姓名等表定义之外的字段。页面按教师灯下整理课稿的场景设计，不要做成生产管理或通用后台模板。

统一主题：暖纸色页面背景 #F3EDE2，卡片 #FFFBF5，导航与主按钮为墨蓝 #1E3348，点缀琥珀 #C17F3E，正向苔绿 #3E6B58，警示赭红 #A65448。标题用衬线中文，正文用柔和无衬线。卡片圆角，悬停时轻微上浮并露出琥珀细边。课次用丝带标签：正课墨蓝、补课琥珀、试听苔绿、学员请假灰、教师取消赭红。授权用印章式小标：是为“已授权”，否为“未授权”。所有列表用卡片，不用密集表格作为主体。空状态写明下一步该做什么，并给出对应按钮。

顶部导航固定。左侧是笺页图标和“青笺课后档案”。右侧标签：灯下台、学员名册、课后记录、档案审阅。当前页高亮。任一操作失败时用简短提示说明失败，不伪造保存成功。

表只有下面这些字段，字段名必须完全一致，禁止编造编号、创建日期或其他字段。两张表都没有自动编号字段，不要生成随机 ID，也不要隐藏一个不存在的 ID。

学员信息字段：学员化名（文本）、学段（单选：小学中段、小学高段、初中、高中）、家长沟通授权（布尔）、课堂状态分享授权（布尔）。
课后记录字段：学员化名（关联学员信息的学员化名）、上课日期（日期）、课次类型（单选：正课、补课、试听、学员请假、教师取消）、课堂速记（文本）、课后档案草稿（指令流，文本输出，不是手工填写）。

数据源写为“学员信息/默认表格”和“课后记录/默认表格”。提交时 data 只写表名“学员信息”或“课后记录”。GetTableCSV 返回无标题行的 CSV，列顺序与 payload 中逗号分隔的字段名一致，按标准 CSV 解析引号。CSV 第 1 行对应行号 1。筛选和搜索只在前端做，但必须保留原始行号。布尔值只使用“是”或“否”。日期使用日期选择器，值为 YYYY-MM-DD。

接口按下面方式调用：
callAppBridge({type:"GetTableCSV", data:"数据源", payload:"逗号分隔的字段名"})
callAppBridge({type:"SubmitRecord", data:"表", payload:"表单JSON文本"})
callAppBridge({type:"GetRecordCount", data:"数据源"})
callAppBridge({type:"GetRecordRow", data:"数据源", payload:"字段名/值"})
callAppBridge({type:"DeleteRecord", data:"数据源", payload:"行号字符串"})
callAppBridge({type:"GetCellBullet", data:"数据源", payload:"字段名/行"})
callAppBridge({type:"GetCellValue", data:"数据源", payload:"字段名/行"})
callAppBridge({type:"SetCellValue", data:"数据源", payload:"字段名/行/值"})
删除前把行号 toString()。新建才用 SubmitRecord，提交后当前行是 1。修改已有记录只按字段依次 SetCellValue，不要再次 SubmitRecord。指令流不放入提交 JSON，也不要用 SetCellValue 改写。关联字段要再取关联表。指令流详情必须用 GetCellValue 取回，并用 Markdown 主题渲染。本应用的指令描述没有要求“以JSON格式输出”，因此提交课后记录后轮询“课后档案草稿”，不要轮询一个不存在的 JSON 字段。

## 灯下台

主标题“青笺课后档案”，副文案“记下课堂里看得见的事实，整理成可审阅的课后草稿”。不要出现效率口号堆砌。

两个主按钮：
“记一节课”进入课后记录并打开空白新建表单。
“新增学员”进入学员名册并打开空白新建表单。

四张统计卡片并列：
学员数：callAppBridge({type:"GetRecordCount", data:"学员信息/默认表格"})。
课后记录数：callAppBridge({type:"GetRecordCount", data:"课后记录/默认表格"})。
本月课次：callAppBridge({type:"GetTableCSV", data:"课后记录/默认表格", payload:"上课日期"})，筛出上课日期属于当前年月的行数。
授权提醒数：callAppBridge({type:"GetTableCSV", data:"学员信息/默认表格", payload:"学员化名,学段,家长沟通授权,课堂状态分享授权"})，统计家长沟通授权或课堂状态分享授权为“否”的学员数。点击这张卡片进入学员名册并套用“未完全授权”筛选。

下方左侧是课次构成：callAppBridge({type:"GetTableCSV", data:"课后记录/默认表格", payload:"课次类型"})，按五个可选项统计，用横向比例条，不用另起页面。下方右侧是学段名册分布：用上面学员 CSV 按学段统计。

最近课稿是纵向时间线卡片，不是表格。数据调用 callAppBridge({type:"GetTableCSV", data:"课后记录/默认表格", payload:"学员化名,上课日期,课次类型,课堂速记,课后档案草稿"})，再调用 callAppBridge({type:"GetTableCSV", data:"学员信息/默认表格", payload:"学员化名,学段,家长沟通授权,课堂状态分享授权"}) 补齐学段和授权。按上课日期降序取 5 条。每张卡片显示学员化名、学段、上课日期、课次类型、课堂速记前 42 字、档案草稿是否已生成。点击卡片进入档案审阅并打开该原始行号的详情。卡片内“查看全部”进入课后记录。

## 学员名册

标题“学员名册”，说明“只维护化名、学段和两项授权；授权会决定课后草稿能否包含家长摘要和课堂状态”。右上按钮“+ 新增学员”。

搜索框匹配学员化名。筛选：全部学段或某一个学段；授权筛选为全部、两项都已授权、未完全授权。

主体卡片字段必须与表单一致：学员化名、学段、家长沟通授权、课堂状态分享授权。列表数据只来自 callAppBridge({type:"GetTableCSV", data:"学员信息/默认表格", payload:"学员化名,学段,家长沟通授权,课堂状态分享授权"})。学段印章可额外调用 callAppBridge({type:"GetCellBullet", data:"学员信息/默认表格", payload:"学段/行号"})，为空时仍显示单元格值。

点击卡片主体打开编辑表单。卡片按钮都要阻止冒泡：
“查看详情”打开侧页，用 GetCellValue 逐字段读取当前行：payload 依次为“学员化名/行号”“学段/行号”“家长沟通授权/行号”“课堂状态分享授权/行号”。
“该学员课稿”进入课后记录并按该化名筛选。
“编辑”同点击卡片。
“删除”先用课后记录 CSV 检查是否已有相同学员化名。有引用时禁止删除并说明要先处理课后记录。无引用时确认后调用 callAppBridge({type:"DeleteRecord", data:"学员信息/默认表格", payload:行号.toString()})，然后刷新。

表单标题“学员信息”，表“学员信息”，字段顺序与卡片一致，全部可见，没有隐藏字段。学员化名必填，提交前与现有化名比对，编辑时允许保留自己的原值，不允许与其他行重复。学段必须使用四个可选项。两项授权用“是/否”开关，默认“否”，不能用 true/false。

新建调用 callAppBridge({type:"SubmitRecord", data:"学员信息", payload:JSON文本})。JSON 只含四个字段。提交后当前行设为 1，关闭表单并刷新，使新记录出现在第一行。
修改依次调用 SetCellValue，数据源“学员信息/默认表格”，payload 形如“学员化名/当前行/新值”。四个字段都更新。若修改了学员化名，保存前提示：已有课后记录不会自动改写关联值。取消只关闭表单，不写数据。

## 课后记录

标题“课后记录”，说明“速记只写可观察事实；提交后由后台整理 Markdown 草稿，教师审阅前它只是预览”。右上按钮“+ 整理新课次”。

搜索匹配学员化名和课堂速记。筛选课次类型、上课日期起止。另有一枚可切换的“只看草稿未生成”。

主体卡片字段与表单字段一致：学员化名、上课日期、课次类型、课堂速记、课后档案草稿。数据调用 callAppBridge({type:"GetTableCSV", data:"课后记录/默认表格", payload:"学员化名,上课日期,课次类型,课堂速记,课后档案草稿"})。关联展示再调用 callAppBridge({type:"GetTableCSV", data:"学员信息/默认表格", payload:"学员化名,学段,家长沟通授权,课堂状态分享授权"})。卡片上速记和草稿只显示摘要，完整内容以 GetCellValue 为准。课次类型可调用 callAppBridge({type:"GetCellBullet", data:"课后记录/默认表格", payload:"课次类型/行号"}) 作装饰。

点击卡片主体进入编辑。按钮：
“查看档案”进入档案审阅并载入该行。
“编辑”打开编辑表单。
“删除”确认后调用 callAppBridge({type:"DeleteRecord", data:"课后记录/默认表格", payload:行号.toString()}) 并刷新。
“在名册中打开”调用 callAppBridge({type:"GetRecordRow", data:"学员信息/默认表格", payload:"学员化名/该化名"})。找到则进入学员名册并打开该行详情；找不到则提示先建学员。

表单标题“课后记录”，表“课后记录”。可编辑字段为学员化名、上课日期、课次类型、课堂速记。课后档案草稿在表单中只读展示，新建时显示“提交后由后台整理生成”，编辑时显示 GetCellValue 得到的 Markdown。不要把草稿做成输入框。

学员化名是下拉，不是自由输入。选项来自学员信息 CSV，显示“化名 · 学段”。选中后就地显示两项授权，并给出事实边界提示：家长沟通授权不是“是”时，提示家长事实摘要不应生成；课堂状态分享授权不是“是”时，提示只保留学习事实、不写课堂状态；课次类型为试听或教师取消时，提示不应生成课时扣减条目；任一关键信息不足时，提示草稿应标注待补充，不要猜测特质或家庭情况。速记框下方固定一句：若速记出现危机信号，后台按技能的危机例外流程处理，教师应优先人工审阅。

新建校验：学员化名必须选中已有学员，上课日期、课次类型、课堂速记必填。上课日期默认今天，课次类型默认正课。提交 JSON 只含四个可编辑字段，例如学员化名、上课日期、课次类型、课堂速记。调用 callAppBridge({type:"SubmitRecord", data:"课后记录", payload:JSON文本})。提交后当前行固定为 1。随即每 2 秒调用 callAppBridge({type:"GetCellValue", data:"课后记录/默认表格", payload:"课后档案草稿/1"})，最多 30 次。等待文案为“正在依据速记整理课后档案，请稍候”。一旦取到非空文本，停止轮询，按 Markdown 显示在表单预览和档案审阅中，并刷新列表。超时则保留记录，提示稍后到档案审阅刷新，不得假装已经生成。

修改时当前行是被点中的原始行号。保存时只对学员化名、上课日期、课次类型、课堂速记依次 SetCellValue，数据源“课后记录/默认表格”。不要提交新记录，不要写课后档案草稿。保存前明确提示：修改速记不会自动重跑整理；需要新草稿时应新建一条课后记录。保存后用 GetCellValue 重读四个可编辑字段和草稿，刷新卡片。

## 档案审阅

这是同一张课后记录的审阅视图，不是新表，也不要另造只读表页面。标题“档案审阅”，说明“右侧是供教师预览的 Markdown 草稿，未经核对不把它当成正式档案”。

左栏是可滚动课稿索引，字段和数据源与课后记录主体一致，默认按上课日期降序。顶部可按课次类型和“已生成/未生成”过滤，并有“刷新”。点击索引项即查看详情。

右栏载入所选原始行号。逐项调用 GetCellValue，数据源“课后记录/默认表格”，payload 为“学员化名/行号”“上课日期/行号”“课次类型/行号”“课堂速记/行号”“课后档案草稿/行号”。再用学员信息 CSV 显示学段和两项授权。顶部事实条显示化名、学段、日期、课次、授权印章。中部稿纸区用 Markdown 主题渲染课后档案草稿；空白时显示“尚未生成”，按钮“重新读取”只再次 GetCellValue，不创建记录。稿纸上方始终显示“预览草稿”。速记原文放在可折叠区，避免与草稿混在一起。

右上角按钮“上一条”“下一条”，按当前索引顺序移动。到头后禁用，不循环跳到不存在的行。
“前往修改”打开课后记录编辑表单并载入该行。
“删除”与课后记录使用同一删除接口和确认。
“核对清单”只存在于当前页面会话，不写回任何字段。四项为：内容能在速记中找到依据；没有猜测特质或家庭情况；试听和教师取消没有扣减条目；未授权时没有家长摘要或课堂状态。四项都勾选后，仅在本次会话把该行显示为“已核对”，刷新页面后恢复未核对。不要因此新增列或调用 SetCellValue。

若草稿文本为空，不显示已核对。若教师从这里删除或修改，返回后按原始行号重新读取；若该行已不存在，清空右栏并提示选择其他课稿。

## 必须实现的行为

每个页面按钮、筛选、搜索、卡片点击、新建、编辑、删除、详情、关联跳转、提交后的轮询和 Markdown 预览都要实现。当前行初始为 0；没有选中行时，依赖行号的上一行、编辑和删除不可用。新建成功后当前行是 1。GetTableCSV 的字段集合必须和对应表单字段一致，这样点击主体卡片才能载入编辑。关联表只通过学员化名关联，显示学段和授权时额外读取学员信息，不把这些关联展示字段写进课后记录。指令流由后台在 SubmitRecord 后异步生成，前端不调用技能、不改指令描述、不手填草稿。全部页面共用青笺主题。
